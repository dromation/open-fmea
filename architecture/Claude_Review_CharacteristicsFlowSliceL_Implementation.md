## 1. What was built

New `CharacteristicLink` model (`django_app/fmea_app/models.py`), extending `StableModel` like every other domain model, placed directly after `ProductCharacteristic`: `from_characteristic`/`to_characteristic` (both real FKs to `ProductCharacteristic`, `CASCADE`, `related_name="outgoing_links"`/`"incoming_links"` respectively — no polymorphic/generic link, per Decision 1), `relationship_type` (a plain `choices` `CharField`, six values — `drives`/`influences`/`affected_by`/`constrained_by`/`supports`/`required_by` — not a scheme/seeded-rows model, per Decision 2), `strength` (a plain `choices` `CharField`, five values — `critical`/`high`/`medium`/`low`/`none`, per Decision 3), `created_by` (a plain free-text `CharField(max_length=255, blank=True)`, matching `RiskEvaluation.actor`'s precedent, per Decision 4). One deliberate, minor correction to the instruction's own literal Section 1.1 field list: it names `created_at = models.DateTimeField(auto_now_add=True)` as a field to add, but `StableModel` (which `CharacteristicLink` already extends) already provides an identical `created_at` field — checked `StableModel`'s definition first rather than assuming. Redeclaring it on the subclass would have been a harmless but dead duplicate, inconsistent with every other model in this file (none of which redeclare it); omitted the redundant line rather than adding dead code. One additive migration, `0013_characteristiclink.py` (the real next-sequential number — migrations through `0012` already exist from Slices A–K), exactly one `CreateModel` operation.

`CharacteristicLinkForm(forms.ModelForm)` covers all five real input fields (`from_characteristic`/`to_characteristic`/`relationship_type`/`strength`/`created_by`), both characteristic querysets ordered by name. Three new views following this app's established list/create/POST-only-action conventions: `characteristic_link_list` (GET filters `relationship_type` and `characteristic` — the latter matching either side of the link via `Q(from_characteristic__pk=...) | Q(to_characteristic__pk=...)`, exactly as Section 1.3 specifies — no AJAX, same server-side-reload pattern as `cause_influence_list`), `characteristic_link_create` (GET renders empty form, POST creates one link per submit and redirects to the list, per Decision 7 no self-link prevention and per Section 1.4 no bulk-create path), `characteristic_link_delete` (`@require_POST`, deletes the one row, redirects to the list — this app's first delete view, following the exact `@require_POST`/no-confirmation-modal pattern already used for every other mutating action in this app, e.g. `add_failure_mode`). Three new routes: `/characteristic-links/`, `/characteristic-links/create/`, `/characteristic-links/<str:stable_id>/delete/`. Two new templates: `characteristic_link_list.html` (filter form + `.table-shell`/`<table>` with the exact six data columns plus a per-row Delete button/form) and `characteristic_link_form.html` (hand-rolled field labels matching every other create-form template's convention in this app).
