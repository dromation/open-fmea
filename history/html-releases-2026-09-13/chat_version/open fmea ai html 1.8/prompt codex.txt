============================================================

Historical application failures are training/engineering knowledge.

Examples already identified:

- GUI renders only shell and workspace remains blank
- old browser/local state breaks newer schema

- GUI drifts from accepted mockup after new features

Preserve these as learning cases.

When Codex finds another real software failure:

1. create validation finding
2. classify failure mode
3. identify effect
4. identify cause
5. identify affected objects/pages
6. create Change Impact
7. implement correction
8. execute regression validation
9. store lesson learned

Do not simply fix bugs silently.

============================================================
10. AI OUTPUT TYPES
============================================================

Where AI assistance exists, distinguish:

FACT
CALCULATION
INFERENCE
RECOMMENDATION

FACT:
directly supported by stored source record.

CALCULATION:
deterministic value calculated by the system.

INFERENCE:
derived interpretation.

RECOMMENDATION:
proposed engineering decision.

Example:

FACT:
DF-SW-001 has S=8, O=5, D=3.

CALCULATION:
RPN = 8 × 5 × 3 = 120.

INFERENCE:
GUI regression remains a relatively important development risk.

RECOMMENDATION:
run responsive regression validation before closing the action.

Do not present recommendations as facts.
